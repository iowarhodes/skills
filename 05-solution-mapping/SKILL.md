# Solution Mapping

Solo-driver mode: without a trio to argue for a wider range of ideas, deliberately push past the first 2-3 obvious solutions — those are usually the ones anyone would think of. The extra value of this step is generating options a single mindset (yours) is prone to skip.

## Core principle

Torres' guidance: generate at least 5-10 solution ideas for one opportunity before converging on which to test. Jumping straight to the first idea (usually "add a feature") skips the divergent thinking that surfaces better, cheaper, or more elegant options.

## Process

### 1. Restate the opportunity
Pull the selected opportunity statement from skill 03's prioritization pick. Keep it visible throughout — every idea should trace back to this specific need.

### 2. Diverge before converging
Generate a wide range of solution ideas, deliberately varying the *type* of solution, not just surface variations on one idea:
- A UI/interaction change
- A content/copy change
- A process or workflow change (doesn't require new UI)
- A "remove something" solution (sometimes the fix is deleting a step, not adding one)
- A "make it visible" solution (surfacing existing functionality customers don't know about)
- An ambitious/bigger-bet version, even if it seems out of scope for now

Aim for at least 5-8 distinct ideas before evaluating any of them.

### 3. Structure as a solution tree layer
Attach each idea as a branch under the opportunity in the tree. Where relevant, note if an idea would also address a nearby sub-opportunity.

### 4. Do a light first-pass filter
Don't fully evaluate yet (that's the next step), but flag any idea that's obviously a non-starter (e.g., clearly infeasible, clearly against a known constraint) so it doesn't waste assumption-testing effort later.

## Output format

- **Opportunity restated**
- **List of 5-10 candidate solutions**, each 1-2 sentences, labeled by type (UI change / content / process / removal / visibility / big bet)
- **Early flags**: any ideas that look like non-starters and why

## When to move on

Once there's a solid divergent set, move to identifying the riskiest assumptions behind the most promising candidates (skill 06) — don't skip straight to building.
